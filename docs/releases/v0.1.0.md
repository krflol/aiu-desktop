# AIU desktop 0.1.0

The first independent Rust desktop release uses one Go backend for credentials,
OAuth, account switching, usage polling, caching, and recommendations. The
upstream SwiftUI application stays independently maintained.

## Downloads and installation

- Rust desktop bundles: Windows amd64, Linux amd64, macOS amd64 and arm64.
- Standalone Go CLI: Windows, Linux, and macOS, each for amd64 and arm64.
- Every archive includes a SHA-256 sidecar and `BACKEND.txt` source provenance.

Download `install.py` and run:

```sh
python3 install.py                       # Swift/Homebrew on macOS; Rust elsewhere
python3 install.py --frontend rust       # Rust on any supported desktop platform
python3 install.py --frontend swift      # Upstream SwiftUI on macOS
python3 install.py --cli-only            # Standalone Go CLI
```

On Windows, use `py -3` instead of `python3`. Python 3.9+ is required. The
installer verifies archive checksums and prints the launch command. It leaves
account stores, PATH, registry settings, and existing installations untouched.
Windows/Linux arm64 currently have CLI archives only.

## Behavior

The panel supports import, login, sync, switching, and removal through the
versioned Go process contract. Cancel and Quit close pending OAuth listeners;
an exchange already in progress finishes saving issued credentials before
shutdown. Closing a browser tab cannot itself be detected; Cancel remains
available in the panel.

Close-to-tray, Show, Refresh, and Quit use native tray integration. Windows
wakeups keep tray commands responsive while hidden or covered. Linux without
a StatusNotifier host keeps a reachable window and exits when it is closed.

The Go source is pinned to `4ed0bbabb965c927d97c549d461f088d13403cae` pending
[upstream PR #11](https://github.com/getparable/aiu/pull/11). Its own version is
0.1.3; frontend and backend version numbers are independent. Backend update
checks still target upstream `getparable/aiu`.

## Validation and limitations

Release publication requires native Rust and Go tests on Windows, Linux, and
both macOS architectures, plus installer tests and Linux tray/no-host smoke
tests. Native Windows tray hide/show, Refresh, and Quit while covered were also
checked locally against the packaged executable. Process tests use the actual
Go child and isolated stores to check cancellation and reaping.

Linux desktop requires GTK 3, Ayatana AppIndicator 3, xkbcommon for X11, a session
bus, and a graphical display. On Ubuntu, install `libgtk-3-0`,
`libayatana-appindicator3-1`, and `libxkbcommon-x11-0`. Linux tray CI uses a synthetic host; individual
desktop extensions and live-provider approval still need manual verification.
Windows/Linux arm64 CLI binaries are cross-built rather than natively tested.

Rust macOS apps are ad-hoc signed and are not notarized. Gatekeeper may block
them; the default macOS choice remains upstream SwiftUI through Homebrew.
The complete original Rust backend fork remains separate, with no automatic
credential-store migration.
